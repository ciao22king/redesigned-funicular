## Decisioni di design (da non perdere)
- **I numeri del profilo non si memorizzano**: si derivano da `skills`/`metrics`
  con `creatorStats`, come la dashboard. Così pagina pubblica e dashboard non
  possono divergere. In `profiles` sta solo ciò che la persona scrive.
- **Badge = fatti verificabili**: founding (data account), verified (flag
  moderazione), top author (≥5 skill e ≥50 stelle, `TOP_AUTHOR`), featured
  (una skill in homepage). Regole in `profile.ts` → pagina/directory/sitemap
  non possono divergere.
- **Profili vuoti o sospesi** = fuori da directory, sitemap e indicizzazione
  (`isProfileIndexable`), ma la pagina risponde comunque (no 404) e senza
  direttiva di index.
- **Editor solo per il proprio login**: il login viene dalla sessione, mai dal
  body.
- `audit.ts` `AUDIT_ACTIONS` esteso con `profile.update` e `profile.report`.

## Skill pages at `/skills/[owner]/[slug]` (task "Pagina skill")

Shipped and deployed (Worker version `5240c0e3-58d0-4477-97e1-92891146d364`,
commit `a15d366`, branch `cloudflare-workers`).

**Routing — one catch-all, not two dynamic segments.** Next refuses a static
`category` segment beside a dynamic one at the same level, so
`/skills/[[...slug]]/page.tsx` (optional catch-all) serves all four shapes:
`/skills`, `/skills/category/<id>`, `/skills/<slug>`, `/skills/<owner>/<slug>`.
The one-segment form resolves via `resolveSlug()` and **308**-redirects to the
canonical two-segment URL. `/s/[owner]/[slug]` is now a bare `permanentRedirect`
to `/skills/...` (308), not a page. Never make a route component that only
redirects `async` and return `void` — TS2786: JSX needs a ReactNode, so end with
`return null`.

**Data.** `migrations/0011_skill_pages.sql` adds `skills.category` (TEXT, default
`other`, indexed) and `skill_versions` (one row per distinct content).
`categoryFor()` in `src/lib/skill-page.ts` is the closed taxonomy: **tags decide
outright if any tag matches** (else the text does, word-boundary matched, so
`api` doesn't fire in `capital`). `upsertSkill` calls `recordVersion`, which
appends only when the FNV-1a `contentHash` changes — republishing is a no-op.
Applied to remote D1 and backfilled: `plan`→`code`, `no-ai-slop`→`design`.
`skill_versions` rows also need `deleteSkill` to clean them up (it does now).

**Counters.** `skillCounters()` in `metrics-db.ts` sums `download`/`copy` over
the *whole life* of a skill (no day window). `copy` had to be added to
`CLIENT_ASSERTABLE_EVENTS` — it is the one outcome event a client may assert,
because only the browser can observe a clipboard write and it changes no ranking.
`download` stays server-observed (the detail route records it).

**Fork.** `/create/from-skills?fork=<owner/slug>` — `CreateFlow` reads the query
on mount with `new URLSearchParams(window.location.search)`, **not**
`useSearchParams` (which would force a Suspense boundary), then fetches
`/api/marketplace/detail` and prefills the paste box.

**Tests.** 335 pass (was 319); `tests/skill-page.test.ts` is new. tsc clean,
`npm run build` clean. Two test failures during development were real logic
bugs, not bad tests: `categoryFor` let text outweigh a tag, and `pickRelated`
let popularity alone qualify a skill — stars are now a tie-break only.

**Live checks.** `/skills`, `/skills/ciao22king/plan`, `/skills/category/code`
and `/skills/category/design` → 200; `/skills/plan` and `/s/ciao22king/plan` →
308 to the canonical URL; unknown skill → 404. JSON-LD `@graph` carries
CreativeWork + Person + BreadcrumbList. `POST /api/metrics` with `copy` → 204 and

block from the layout, so a page has two ld+json scripts — expected.

## Mail custom: Cloudflare Email Routing, NON ImprovMX (2026-11-10)
Richiesta utente: "setuppamela così mi arrivano le mail". La zona
`skillforge.cc.cd` (id `bfc64fb636f77ec4b0f9707737aecd17`, attiva) **aveva gia'**
Cloudflare Email Routing attivo e `synced`, con destinazione
`ciao22king@gmail.com` **verificata** e la sola regola `admin@` -> Gmail.
L'utente stava per incollare i record **ImprovMX** (MX `mx1/mx2.improvmx.com`,
SPF "misto"): sarebbe stato un **conflitto** — due sistemi di ricezione sulle
stesse MX, e l'SPF misto manderebbe in spam. ImprovMX non serve.

**Cosa ho fatto** (API, scope OAuth `email_routing:write` presente):
`PUT /zones/<zone>/email/routing/rules/catch_all` con
`{enabled:true, matchers:[{type:'all'}], actions:[{type:'forward',value:['ciao22king@gmail.com']}]}`.
Il catch-all esisteva ma era **disattivato con azione `drop`**: da qui il "non
mi arrivano le mail". Ora `*@skillforge.cc.cd` inoltra tutto a Gmail; resta anche
la regola `admin@`.

**Credenziali DNS: ancora negate.** Il token OAuth di Wrangler ha **`zone:read`**,
non write: `GET/POST /zones/<zone>/dns_records` -> **403 Authentication error**.
Quindi i record DNS non li posso toccare (ma non serviva: erano gia' giusti).
Il secret `$Cloudflare` e' un placeholder non valido (`CLOUDFLARE_API_TOKEN
cfut_...`). Per editare il DNS serve un API token con **Zone:DNS:Edit**.
Endpoint utili: `/zones/<z>/email/routing`, `/email/routing/rules`,
`/email/routing/rules/catch_all`, `/accounts/<a>/email/routing/addresses`.
Email Routing = **solo ricezione**; per *inviare* come `@skillforge.cc.cd` serve
SMTP esterno o Cloudflare Email Sending (beta, scope `email_sending:write`).
